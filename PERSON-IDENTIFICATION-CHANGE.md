# Change: PostHog Person Identification on Form Submit

**Date:** 2026-06-10
**Files changed:** `js/dtp-breakdance-forms.js`, `dtp-posthog-tracker.php`, `README.md`

---

## The Problem

Before this change, every visitor was tracked in PostHog under an **anonymous `distinct_id`** (a random UUID generated by posthog.js, also stored as `$device_id`).

When someone filled in a Fundcanna lead form (Breakdance or Ninja Forms) and submitted it:

- The "Form Submitted" event was sent, but it stayed attached to the visitor's **anonymous** `distinct_id`.
- PostHog had no idea the anonymous visitor was actually `jane@example.com` — there was no PostHog **Person** profile carrying their email/name/phone.
- Their prior anonymous activity on the site (pageviews, UTM source, the `fundcanna_form_submit_attempt` click event, etc.) stayed siloed under the anonymous ID and never merged into a profile for that lead.
- This made it hard to do person-level analytics in PostHog (e.g. "show me everything this lead did before converting") and limited what downstream tools (like the Salesforce pipeline) could associate with the lead's profile.

In short: **we were capturing the form submission event, but never telling PostHog "this visitor IS this person."**

---

## The Solution

When a form (Breakdance **or** Ninja Forms) is submitted successfully and contains an email address, the plugin now calls PostHog's **`identify`** API to link the visitor's anonymous profile to a known person — *but only if they aren't already identified*.

### Breakdance (client-side — `js/dtp-breakdance-forms.js`)

Inside `captureEvent()`, before the "Form Submitted" event is sent:

1. `findEmail(properties)` scans all submitted field values for one that looks like an email address (no specific field name required).
2. If the visitor's current `distinct_id` already differs from their anonymous `$device_id`, they're already identified — skip.
3. Otherwise, build `$set` properties (`email` + any field matching `name|phone|mobile|tel`) and call:
   ```js
   window.posthog.identify(email, setProps);
   ```
4. Because `identify()` updates the locally persisted `distinct_id` immediately, the "Form Submitted" event sent right after is recorded against the same identified person.

### Ninja Forms (server-side — `dtp-posthog-tracker.php`)

Inside `send_form_to_posthog()`, after the field properties are built:

1. `find_email_in_properties()` scans all field values for a valid email (`filter_var(..., FILTER_VALIDATE_EMAIL)`).
2. `get_posthog_anon_distinct_id()` reads the visitor's anonymous `distinct_id` from the `ph_<api_key>_posthog` cookie that posthog.js already sets in the browser.
3. If that anonymous ID already equals the email, the visitor is already identified — skip.
4. Otherwise, `send_identify_event()` sends a `$identify` event to PostHog with `$anon_distinct_id` set to the cookie's value, telling PostHog to merge the anonymous person's history into the new email-based profile.
5. The main Ninja Forms event's `distinct_id` is then set to the email, so it's recorded against the same identified person.

---

## Why This Approach

- **No extra config needed per form.** Auto-detecting the email by value pattern means it works for any Breakdance or Ninja Forms field, regardless of how the field is named/keyed.
- **Idempotent / safe to run on every submission.** The "already identified" checks (comparing `distinct_id` vs `$device_id` on the client, and `distinct_id` vs `email` on the server) prevent redundant `identify`/`$identify` calls once a visitor has already been linked to their email.
- **Preserves history.** Using `$anon_distinct_id` (server-side) and `posthog.identify()` (client-side) merges the visitor's pre-submission anonymous activity (pageviews, UTM params, the `fundcanna_form_submit_attempt` event) into their new Person profile — giving a complete picture of the lead's journey.
- **Consistent across both form builders.** Both Breakdance (client) and Ninja Forms (server) now follow the same identification logic, just implemented on the appropriate side of the request.

---

## Result

After this change, as soon as a lead submits a form with their email, PostHog creates/updates a **Person profile** with their email (and name/phone if present), merges their prior anonymous session activity into that profile, and all subsequent events (including the "Form Submitted" event itself) are recorded against the identified person rather than an anonymous ID.
